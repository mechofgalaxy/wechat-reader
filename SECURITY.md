# Security and privacy

Use only data you own or have explicit authority to read. Never publish databases, keys,
access bundles, contacts, raw messages, decoded private media or personal configurations.
Public issues should contain a fictional reproduction and redacted error code only.
For sensitive issues, use GitHub private vulnerability reporting if enabled; otherwise do
not post the details publicly. There is no promised response SLA for this preview.

Database reads use temporary snapshots/query-only connections. Persistent outputs require
explicit commands and are private by default. Account paths/materials are checked against the
selected profile. No messaging commands are provided. Optional first connection bundles a restricted experimental acquisition helper; ordinary reads never execute it.

The installer contacts public software distributors; explicit model installation contacts
Hugging Face. Ordinary reading/OCR/transcription does not send chat data to those services.
Cloud assistants receiving selected output have their own data-processing boundary.
Keep releases and optional dependencies up to date; pinned hashes ensure reproducibility,
not a claim that third-party code is free of vulnerabilities.


First connection is a separate opt-in operation, outside normal read-only queries.
Read START_HERE.md before use. The human must confirm process access, restarts and
shadow signing in the native UI, then enter any password only in macOS's own
administrator prompt. Acquisition does not upload chats or keys. Output returned
to a cloud agent during later queries enters that provider's context. No agent may
approve its own dialogs, automatically retry acquisition or remove recovery locks.
